# Architecture

bambiui is a local-file-copy UI component CLI. The repo is intentionally small and source-distributed: the CLI writes framework-ready source into the user's project.

## Active flow

```txt
src/core -> src/generator -> src/registry -> src/cli -> user/template project
```

## Layers

### `src/core`

Source of truth for component behavior, shared DOM helpers, and styles.

Current components:

- `button`
- `tabs`

Core components should be framework-agnostic and use serializable DOM state through `data-*` attributes.

### `src/generator`

Generic install planning and source transformation.

Responsibilities:

- build install plans
- validate requests/plans
- resolve copy/text files
- transform authoring imports into installed relative imports
- write generated managed files such as `auto-init.ts` and `styles/index.css`

The generator should not know about React/Solid/Svelte/Vue implementation details.

### `src/registry`

The registry connects core components to framework providers.

Responsibilities:

- declare component files/helpers/styles
- hold parsed component metadata
- expose framework artifact generators
- provide import hints

Framework-specific output belongs under:

```txt
src/registry/frameworks/*
```

### `src/cli`

User-facing commands.

Current commands:

```sh
bambi init
bambi doctor
bambi list
bambi add <component>
```

The CLI should remain thin: read config, call registry/generator, write files, and print actionable results.

## Managed files

Managed files are regenerated by the installer and safe to update:

- `auto-init.ts`
- `styles/index.css`
- framework helper files marked as managed by registry providers

User-owned component/style files are skipped unless `--force` is passed.

## SSR safety

Generated `auto-init.ts` must not directly access `document` during module evaluation or server rendering. `autoInit()` and `destroyAll()` should no-op when no DOM root exists.

## Template validation

`apps/templates/*` fixtures exercise the CLI in realistic project layouts. `scripts/smoke-templates.mjs` copies each template, runs `init`, installs `button` and `tabs`, asserts files, checks for forbidden internal imports, and compiles generated TypeScript/TSX with stubs.

## Replacement strategy

This repo replaces the old `platform` monorepo incrementally. Do not copy old generated artifacts as a compatibility layer. Instead, migrate components one by one into `src/core/components` and expose them through the local registry.
